# Licensing Decision - BUSL-1.1

- Initial decision: 2026-07-20
- Packaging contract updated: 2026-07-22
- Initial license commit: `c319180`

This is an engineering record, not legal advice. File declarations and artifact hashes can be tested; copyright ownership, attribution sufficiency, commercial terms, and enforceability require qualified counsel.

## Decision

The Provenance application is licensed under Business Source License 1.1 with:

| Parameter | Value |
| --- | --- |
| Licensor | Anol Deb Sharma |
| Additional Use Grant | None |
| Change Date | Four years after each version's first public distribution |
| Change License | Apache-2.0 |

BUSL-1.1 is source-available, not an OSI open-source license. With no Additional Use Grant, the license text permits non-production use. It does **not** provide a general exemption for internal production use; production use requires a commercial license until that version's Change Date. Each version is evaluated under its own applicable dates and terms.

## Repository contract

The application identifier is declared consistently as `BUSL-1.1` in:

- `package.json`
- The root package entry in `package-lock.json`
- `src-tauri/Cargo.toml`

The complete license text is in the root `LICENSE`. `scripts/license-policy.mjs` validates both the declarations and the authenticated BSL text, while `.gitattributes` fixes `LICENSE` to LF so policy and packaged artifact digests are reproducible on Windows checkouts. Stale application-source `Apache-2.0` SPDX headers were changed when the root license was introduced so they no longer contradict the intended application license.

## Artifact contract

The application license and third-party obligations are different resources:

| Resource | Production release | Unsigned pilot |
| --- | --- | --- |
| Root application `LICENSE` | Required, hash-bound top-level resource | Included |
| `dist/THIRD_PARTY_NOTICES.txt` | Required | Included |
| `dist/RUST_THIRD_PARTY_NOTICES.txt` | Required, generated by pinned `cargo-about` | Required, generated by the same pinned tool |
| `node/node.exe` | Exact version/hash/signer required | Required and hash-bound; production signer policy is not asserted |
| `node/LICENSE` | Required and independently hash-bound | Required and hash-bound with the local Node runtime |

The production release plan, unsigned payload, installed resource inventory, bundled record, and release/updater attestations bind the root application license. Omitting or changing it fails release verification.

The pilot's complete application/runtime notice inventory does not make it
distributable. Its bounded evidence sidecar binds the local installer, runtime
manifest, Node executable, and each license/notice resource. It remains
unsigned, uses a local updater key and deliberately unavailable command
sandbox, does not authenticate the local Node runtime under the protected
vendor-signing policy, and has no protected release attestation. Legal review
is still required before external distribution. The sidecar separately records
the validated `cargo-about` executable/version and `Cargo.lock` hashes that
produced the Rust notice inventory.

## Rationale

The source must remain inspectable for the project's auditability claim, while the project owner wants to reserve production commercialization before each Change Date. BUSL expresses that tradeoff more clearly than an absent license or an informal README restriction.

Alternatives previously considered included Apache-2.0, a shorter source-available change license, and a fully proprietary license. The current decision favors readable source plus time-delayed Apache-2.0 conversion while reserving present production rights.

## Open legal and operational questions

- Confirm ownership and attribution for any material code derived from an earlier Apache-2.0 scaffold. Changing an SPDX header cannot remove obligations the licensor does not own.
- Prepare a separate commercial agreement covering price, scope, support, warranty, security obligations, updates, termination, and data processing before production use by a customer.
- Determine the exact first-public-distribution date for each released version and preserve it as Change Date evidence.
- Review third-party JavaScript, Rust, Node, NSIS, WebView2, Docker-image, icon, and branding obligations for every distributable artifact.
- Decide trademark ownership and usage rules for `Provenance`; BUSL grants no general trademark right.
- Have counsel review the completed signed installer and notice inventory before first external distribution.
